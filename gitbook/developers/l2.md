## Protocol shape (for implementers)

The target design has six parts:

1. **Parallel tips** — each ledger advances independently; no event means no block.
2. **L1 birth certificate** — a tip binds to a unique CoNET L1 NFT and exactly one class: **asset**, **storage**, or **trade**.
3. **EIP-155 Chain ID vs Group ID** — plane id is **CoNET-DLE Testnet** `0x44c45`; each live group’s user-visible **Group ID** is its L1 register tx hash; L1 uint `groupId` is a storage key only. G2’s user-visible id is `0xf781f2c2…876d5153` (see [Lab gather](#lab-gather-2026-08-16-reviewed-2026-08-18)). None of these is CoNET L1 `224422` or the tip NFT id (whitepaper §5.2.0d). Route history from the deployed L1 [Global Archive Routing Registry](../l2/routing-registry.md).
4. **Validator production** — a per-tip committee proposes event blocks (current design: seven selected validators, five-signature threshold). This is **not** the CoNET L1 validator set. Archives do not produce blocks.
5. **Archive finality** — the hosting archive group replays the candidate and finalizes with Tendermint-style prevote / precommit certificates.
6. **Separated economics** — protocol value fees, execution reserves, and availability budgets are different ledgers.

Class is immutable. A tip cannot host arbitrary bytecode or become a general-purpose VM. Digest: [ledger classes](../l2/tip-classes.md), [archive plane](../l2/archive-plane.md), [economics](../l2/economics.md).

## ERC-20 path into DLE (not live)

A foreign ERC-20 must already be a Treasury-canonical CoNET L1 token. See [Bring an ERC-20 into CoNET](l1-erc20-bridge.md). DLE never burns a foreign-chain contract directly.

```text
Treasury-canonical ERC-20 on CoNET L1
        │  exact proxy + version
        │  AssetAdmissionRegistry = ACTIVE
        │  approved pool + frozen TWAP adapter
        ▼
BURNED_PENDING   →   ACTIVATED  (or REFUNDED if genesis misses the deadline)
        │
        ▼
asset-class tip  (claim against burned units, not a wrapped L1 transfer)
```

Even conet-USDC must pass those gates in the design. Production asset ingress and new-chain admission remain **disabled** pending measured economic evidence. Digest: [Cross-chain assets in DLE](../l2/cross-chain-assets.md).

## Suggested implementation order

1. Clone [CoNET-DLE](https://github.com/CoNET-project/CoNET-DLE) and pin the whitepaper revision you implement.
2. Pick **one** boundary: Archive conformance, Asset gateway invariants, or Operator-domain identity. Do not mix requirements across files without citing both.
3. Implement against the spec’s frozen vectors / schemas. Record the revision in your artifact.
4. Keep L0 coordination (wallet-addressed envelopes) and L1 settlement (Treasury, CNET gas) as **external** dependencies. DLE does not replace Layer Minus or CoNET L1.
5. Stop at the documented production blockers: second independent Archive implementation, wrapper / networking / custody gates, and formal-verification release items in the Asset spec.

## What not to claim

- Do not describe GitBook pages as the wire encoding.
- Do not treat Explorer-verified Treasury bytecode as an `AssetBurnMintGateway`.
- Do not use L1 validator counts as a DLE committee census.
- Do not invent additional `dle.*` hostnames. The authorized lab explorer is [https://dle.conet.network/](https://dle.conet.network/). Do not write that hostname into Solidity.
- Do not treat `0x44c45` as CoNET L1 or as Group ID. Do not display L1 uint `1` or `2` as Group ID. The first group’s user-visible Group ID is the L1 register transaction hash. The lab M6 second Group ID is the G2 L1 `registerLiveGroup` tx; laboratory keccak is an alias only.
- Do not present a successful L1 bridge as “the asset is on L2.”
- Do not treat lab M6 fission, M7 typed roots, laboratory Archive Certificates, HTTP `:27101` gather, or repository EIP-712 unit tests as production DePIN or as the start of 30-day qualification.
- Do not treat `npm run runtime:test` **159/159** as evidence that all seven live G1 hosts stay healthy. **P23** keep-deploy evidence is landed as **6/7 `LIVE_OK`** plus fd-01 new-chain 409→accept; official standby fd-06 HTTP is unstable (later remapped). **P24** wires isolated `node.ts` only. Do **not** write 7/7 healthy.
- Do not treat a started 30-day clock, a non-green Explorer clock chip, or public SPA `index-C8IdTq4H.js` as 30-day qualification. `pilotQualified` stays false. Do **not** invent P26.
- Do not treat an elapsed 30-day wall clock as `PilotQualificationGate` success. The operator clock facade intentionally returns `pilotQualified: false`; rotations, re-homes, and takeovers require independent terminal evidence.
- Do not treat `inventoryFrozen` as a frozen roster. It blocks new hash-catalogue writes, not replay/catch-up locator writes or roster expansion.
- Do not consume `officialStandbyReadyCount=4` as proof of four official standbys. The frozen formal boundary is two; the observed four is a classification drift caused by extra standby roles entering the count.
